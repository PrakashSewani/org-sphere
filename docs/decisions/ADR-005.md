# ADR-005: Separated Billing Architecture

## Status

Accepted

## Date

2026-07-13

## Context

OrgSphere needs to support two deployment models:
1. **SaaS (Cloud)** — Subscription billing via Stripe
2. **Self-Hosted** — One-time license purchase, deployed on client servers

The billing/payment system must be completely separate from the core application so that:
- Self-hosted deployments have zero billing dependencies
- The core app has no Stripe SDK, no payment logic
- License validation works fully offline for self-hosted
- The billing service can evolve independently

## Decision

OrgSphere will use a **separated billing architecture**:

1. **OrgSphere Core** — No billing code. Only validates license status via `ILicenseValidator` interface.
2. **OrgSphere.Billing** — Separate repo, separate deployment. Handles Stripe integration, subscription lifecycle, license key generation.
3. **License keys** — RSA-signed, validated offline with embedded public key. No network call required.

### Architecture

```
OrgSphere Core          OrgSphere.Billing (separate repo)
├── No Stripe SDK       ├── Stripe integration
├── No payment logic    ├── Subscription management
├── ILicenseValidator   ├── License key generation
└── Graph + Org logic   └── Payment processing
```

## Consequences

### Positive

- Self-hosted deployments have zero external dependencies for licensing
- Core app remains clean — no billing contamination
- Billing service can use any stack (could even be Node.js if preferred)
- License validation is instant (no network call)
- Two deployment models share the same core codebase

### Negative

- Need to maintain two repos
- License key rotation requires re-deployment for self-hosted
- No real-time license validation for self-hosted (offline = trust-based)

### Neutral

- Billing service needs its own CI/CD pipeline
- License key format needs documentation for enterprise customers

## Alternatives Considered

1. **Billing in core app**: Rejected — contaminates core with payment logic, breaks self-hosted
2. **Online license validation**: Rejected — self-hosted customers won't have internet access during deployment
3. **License server**: Rejected — adds infrastructure dependency for self-hosted
