# ADR-002: Multi-Tenant SaaS Architecture

## Status

Accepted

## Date

2025-01-15

## Context

OrgSphere is designed as a commercial SaaS platform. Each customer needs isolated data, configuration, and users. The architecture must support thousands of tenants while maintaining performance and security.

## Decision

OrgSphere will use a schema-per-tenant approach for most customers, with database-per-tenant for enterprise customers requiring maximum isolation. Each tenant gets a dedicated schema within a shared database cluster.

## Consequences

### Positive

- Strong data isolation
- Easy backup/restore per tenant
- Simple data deletion for GDPR
- Cost-effective for most tenants
- Scalable to thousands of tenants

### Negative

- More database connections
- Schema migration complexity
- Tenant context propagation required
- Cross-tenant analytics more complex

### Neutral

- Need tenant routing middleware
- Need schema management tooling
- Need to design migration strategy

## Alternatives Considered

1. **Database per tenant**: Maximum isolation, higher cost
2. **Shared schema with tenant_id**: Weaker isolation, simpler management
3. **Row-level security**: Complex, potential for errors
